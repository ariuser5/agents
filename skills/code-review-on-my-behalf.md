# Code Review On My Behalf

Use only when the user explicitly asks for a code review, review comments, or
responses to review feedback on their behalf.

1. Use `personas/pragmatic-reviewer.md` instead of the default persona.
2. Read the applicable repository instructions, change set, surrounding code,
   tests, and existing review discussion before reaching conclusions.
3. Prioritize correctness, regressions, security, maintainability, and missing
   validation. Report findings first, ordered by severity and tied to locations.
4. Write each proposed comment or reply as concise, ready-to-post first-person
   text. Keep evidence separate from inference and never claim unverified work.
5. If responding to feedback, verify the concern before agreeing, explaining,
   or proposing a resolution.
6. State explicitly when no findings are identified and name any remaining
   uncertainty or testing gap.

Draft only unless the user explicitly authorizes submission. Do not modify code
unless requested. Do not create commits or push branches as part of this skill.
